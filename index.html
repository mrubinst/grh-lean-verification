What exactly is claimed

Main.lean proves five theorems with no hypotheses:

theorem riemannHypothesis : RiemannHypothesis
theorem riemannZeta_eq_zero_re : RiemannZetaZerosOnLine
theorem LFunction_ne_zero_of_half_lt_re : DirichletLNonvanishingRightOfHalf
theorem LFunction_eq_zero_re : DirichletLZerosOnLine
theorem LFunction_eq_zero_re_of_isPrimitive : PrimitiveDirichletLZerosOnLine

RiemannHypothesis is Mathlib's definition (Mathlib/NumberTheory/LSeries/RiemannZeta.lean, at the pinned commit):

def RiemannHypothesis : Prop :=
  ∀ (s : ℂ) (_ : riemannZeta s = 0) (_ : ¬∃ n : ℕ, s = -2 * (n + 1)) (_ : s ≠ 1), s.re = 1 / 2

This says that every zero of ζ other than the trivial zeros −2, −4, … has real part ½. The clause s ≠ 1 only excludes the pole, where Mathlib gives ζ a placeholder value. The other statements are in Statements.lean (SHA-256 79ef7ca7…33b47bf), which imports nothing but Mathlib:

def DirichletLNonvanishingRightOfHalf : Prop :=
  ∀ (N : ℕ) [NeZero N] (χ : DirichletCharacter ℂ N) (s : ℂ),
    1 / 2 < s.re → (χ ≠ 1 ∨ s ≠ 1) → DirichletCharacter.LFunction χ s ≠ 0

def DirichletLZerosOnLine : Prop :=
  ∀ (N : ℕ) [NeZero N] (χ : DirichletCharacter ℂ N) (s : ℂ),
    0 < s.re → s.re < 1 → DirichletCharacter.LFunction χ s = 0 → s.re = 1 / 2

In words: for every modulus N, every Dirichlet character χ mod N (primitive or not), and every s with Re s > ½, L(s, χ) ≠ 0, except at the pole s = 1 of the trivial character. That is the Generalized Riemann Hypothesis for Dirichlet L-functions. It is not GRH for Dedekind zeta functions or for automorphic L-functions in general. RH is the case N = 1.

Why "assumed RH" would be detectable: the theorems have nothing to the left of the colon, so there are no hypotheses. Inside the project there are conditional steps such as rh_of_every (h : EveryCharacter) : RiemannHypothesis, but the final term supplies h by a proved theorem (allChi). The kernel accepts a closed theorem only if every such hypothesis has been discharged. The one remaining way to "assume" something is an axiom, and #print axioms lists them all.

How the top level fits together

The step from "no zeros right of ½" to "zeros on the line" (Formalism/GammaFactorNonvanishing/CritLine.lean) is a short, standard argument using the functional equation, applied to χ⁻¹ at 1 − s. We have read it.

  • …/CutCptCopy.lean: a command that copies declarations with renamed constants via addDecl. addDecl sends each copy to the kernel.
  • …/OwnStruct.lean, …/HeckeNonvanishing/Imports.lean: tactics (kcopy, kexactB) that assign a goal directly instead of going through the elaborator's unifier. The kernel still checks the resulting proof term when the theorem is added.

None of this is needed for trust. A kernel replay does not run tactics; it re-checks the finished terms.

How we are building it

A plain lake build worked but was slow. With 175k modules, Lake's own dependency bookkeeping used 110–160 cores, kept only 20–30 compiles running at once, and pointed to a finish in roughly 17 hours. Loading Mathlib's 6.4 GB of .olean files over NFS was a further 6–40× penalty per module. So the build now runs as follows:

  • Each server holds a local copy of the Lean toolchain, Mathlib's official prebuilt cache, and the sources.
  • A small scheduler (coord.py, agent.py) compiles each module with lean directly. It uses the same options Lake passes (package name, lakefile options, the per-library option for GroundTheory.LocalFields/GlobalFields, --tstack). A module is started on a machine only once every module it imports is present on that machine's disk.
  • We checked that this invocation gives byte-identical .olean files to Lean run with Lake's own generated setup file for the same module.
  • Correctness does not depend on the scheduler: the kernel replays below re-check every declaration, however the files were produced.

What a successful check will and won't mean

If the compile succeeds, the axioms are only the standard three, and both kernels accept, then the theorems above are proved. This assumes only that the Lean kernel (checked twice, by independent implementations) is sound and that Mathlib's definitions of ζ and of Dirichlet L-functions mean what they are supposed to. Those definitions are long established and come with the Euler product, the functional equation, ζ(2) = π²/6 and the prime number theorem.

A successful check says nothing about whether a human can understand the proof. That is a separate and much larger project.
